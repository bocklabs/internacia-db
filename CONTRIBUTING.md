# Contributing to Internacia Datasets

Thank you for contributing. This repository is **data-as-code**: the YAML files under `data/countries/`, `data/intblocks/`, and `data/blocktypes/` are the authoritative sources. Everything under `data/datasets/` is generated by the build.

## Setup

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements-dev.txt
pre-commit install   # optional but recommended
```

## Editing data

### Countries (`data/countries/*.yaml`)

- One file per entity, named by ISO 3166-1 alpha-2 code (e.g. `US.yaml`).
- Required fields: `code`, `name`, `iso3code`, `numeric_code`, `entity_type`, `code_status` (see `data/schemas/countries.schema.json`).
- Non-ISO codes need explicit `code_status` (`user_assigned`, `obsolete`) and a `recognition_status` block — see [docs/country-code-policy.md](docs/country-code-policy.md).
- `population`/`area`/`gini` are structs: `{value, year, source, source_id}`. **Never use `year: 0`** — omit the year if unknown.
- Add a `provenance` entry whenever you set or update an enriched field. Validation warns when a record has fewer than four provenance entries (`INSUFFICIENT_PROVENANCE`; threshold in `data/schemas/*_completeness.yaml`).
- See [docs/enrichment.md](docs/enrichment.md) for refresh cadence and maintainer commands.
- Crosswalks (`geonames_id`, `ioc_code`, `fifa_code`, `fips_code`) are optional reference ids — not socioeconomic fields.

### Intblocks (`data/intblocks/<category>/*.yaml`)

- Filename stem must match record `id` exactly (uppercase ASCII; see id rules in
  [intblock-inclusion-policy.md](docs/intblock-inclusion-policy.md)).
- The directory is the primary `blocktype` and must exist in `data/blocktypes/blocktypes.yaml`.
- Required fields: `id`, `name`, `blocktype`, `status` (see `data/schemas/intblocks.schema.json`).
- Set `scope_category` on every formal record (`igo`, `treaty_body`, `policy_forum`, `reference_enumeration`, `intergovernmental_body`, `non_state_organization`); a missing formal category is a validation error. The category describes the entity, not the role of its country `includes` — see [docs/intblock-inclusion-policy.md](docs/intblock-inclusion-policy.md).
- Cite official membership sources in `provenance`. How to search catalogues and improve records: [docs/discovery.md](docs/discovery.md). Catalogues already searched (UNTC, WTO RTA-IS, WTO PTA Database, UNCTAD IIA Navigator, Wikipedia `.int` list) and roster authorities are in [docs/intblock-sources.md](docs/intblock-sources.md).
- Every `blocktype` value must exist in `data/blocktypes/blocktypes.yaml`.
- `includes[].id` is authoritative (ISO alpha-2 for countries); `name` is a display label.
- **`last_verified`** is the date you checked the record against the source in its `provenance`. Every new or changed
  intblock must have one, and a change to `includes` must update it; validation compares your branch with the pull
  request base (`INTERNACIA_BASE_REF` overrides it locally). Tier-1 organizations (`data/watch/rosters.yaml`) are
  overdue after 6 months, all others after 12; `python scripts/last_verified_report.py` prints the counts.
- Dissolved organizations: set `status: historical` and a `dissolved` date. Do not invent membership lists — leave `includes` empty for records that still need research.
- **Quote YAML-boolean lookalikes**: write `'NO'` (Norway) and `'no'` (Norwegian), otherwise YAML parses them as `false`.

## Validating your changes

Run before opening a PR:

```bash
python scripts/validate_countries.py     # 0 = no errors (warnings OK); 1 = errors
python scripts/validate_intblocks.py     # add --fail-on-warning to treat warnings as errors
python scripts/validate_countries.py --json   # structured output for agents
python scripts/builder.py build          # regenerate data/datasets after source edits
python scripts/check_generated_artifacts.py                # local build matches source + each other
pytest tests/                            # unit and integration tests against updated exports
ruff check internacia_builder/ scripts/ tests/             # lint
python scripts/generate_data_dictionary.py --check         # generated field reference
python scripts/check_markdown_links.py                     # internal doc links
python scripts/check_doc_counts.py                         # README/llms/AGENTS vs manifests
```

Commit the regenerated `data/datasets/` descriptors (manifests, `contract.json`,
`datapackage.json`, dataset card, alias JSON) with source changes; git ignores the
binary and bulk exports. Never edit them by hand. Partial builds are useful for local
analysis but do not refresh every descriptor. New records also require updated current-count documentation
and any affected cookbook expectations.

CI checks committed artifact freshness before rebuilding into `.ci-datasets`,
then runs tests against that staging directory. It also checks the quality gate
and release descriptor (`.github/workflows/validate.yml`); the documentation
workflow builds and typechecks the website on PRs.

### Data-quality gate and reports

CI also runs `python scripts/builder.py analyze-quality` and **fails only on
CRITICAL/IMPORTANT** findings; MEDIUM/LOW issues are advisory. The `dataquality/`
report is regenerated on each run and uploaded as a workflow artifact; it is not
committed (`dataquality/` is ignored by git). Use the CI artifact or a fresh local run.

Rule implementations live in a single shared layer
(`internacia_builder/validate/country_rules.py`, `intblock_rules.py`,
`cross_rules.py`) used by both the CLI validators and `analyze-quality`, so a
rule behaves identically in CI gates and in `dataquality/` reports. IMPORTANT-tier
referential-integrity rules (unresolved borders, org references, headquarters
countries, duplicate `wikidata_id`) fail CI; legitimate exceptions are declared in
the documented allowlists in `data/schemas/countries_completeness.yaml`
(`borders.reciprocity_allowlist`) and `data/schemas/intblocks_completeness.yaml`
(`references.org_ref_allowlist`, `references.wikidata_duplicate_allowlist`) with a
reason comment per entry.

## Pull request checklist

- [ ] Validation passes with 0 errors (`validate_countries.py`, `validate_intblocks.py`)
- [ ] Tests pass (`pytest tests/`)
- [ ] Full build outputs are committed with source changes; artifact and documentation checks pass
- [ ] New/changed enriched fields have `provenance` entries (countries)
- [ ] Sources for membership or status changes are cited in the PR description
- [ ] `CHANGELOG.md` updated under `[Unreleased]` for schema or semantic changes

## Larger changes

New capabilities, schema changes, or breaking changes go through an OpenSpec proposal first — see [openspec/AGENTS.md](openspec/AGENTS.md).

## Releases

Maintainers tag releases (`vX.Y.Z`); `.github/workflows/release.yml` rebuilds all formats and attaches them as release assets. Versioning follows [docs/versioning-policy.md](docs/versioning-policy.md) (dataset SemVer) with migration notes in `CHANGELOG.md`.
